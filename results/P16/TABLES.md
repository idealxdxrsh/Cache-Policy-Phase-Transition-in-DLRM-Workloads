# P16 tables: multi-corner timing of the final routed designs on the lab server C2
Generated by `python3 -I tools/p16_collect.py` from the reports copied to ~/c2_results/p16/ (raw reports stay off the repo).
Technology: a commercial 28nm FD-SOI standard-cell library, three corners; the designs were placed, clock-tree
synthesised, routed and optimised (setup and hold) at the typical corner only, so slow- and fast-corner failures are expected.
Flow: cadence/pnr/p16_corners.tcl and run_p16.csh: restoreDesign of the P15 route.enc, two corners added next to the typical view
(create_library_set, create_rc_corner with the corner's RC tech file and temperature, create_delay_corner, create_analysis_view),
setExtractRCMode -engine postRoute, then per corner set_analysis_view (that view only for setup and hold) and timeDesign -postRoute
(setup, hold). No optimisation, ECO, re-routing or saveDesign. Each view switch discards the parasitics and re-extracts them for
the new RC corner (tool warning IMPEXT-3503, then tQuantus extraction at 125 C for SigRCmax and -40 C for SigCmin).
Analysis settings as restored: on-chip variation, CPPR both; the flow sets no derates; SDC as in P15 (clock uncertainty 0,
input and output delay 0.2 x period on an ideal clock), file identical to the P15 run's constraints.sdc.
Designs: d256 merge-off v2/v3 at 1.0 ns (_nodvtsh2, after two hold passes) and 1.1 ns (_nodvts), d16 v3 at 0.8 ns (_nodv).
